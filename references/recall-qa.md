# 召回评测与验收清单

交付前逐项检查，记录通过、未通过或未执行。可以补检时，按缺口补检并重新检查。若调整检索边界或停止规则，更新检索方案版本并记录理由。

## 一、数据覆盖

检查候选池在四个维度上的分布是否有未声明的缺口：

| 维度 | 检查问题 |
| --- | --- |
| 来源与方法 | 预定的主要来源和补检是否执行？把已查无命中、只查了部分和未执行分开记 |
| 语言 | 检索方案列出的语言是否都有实质产出？某语言产出为零要写原因 |
| 年代 | 是否符合检索方案的时间范围？原典、政策版本或早期研究有无已知缺口？ |
| 文献类型 | 期刊 / 学位论文 / 会议 / 报告的构成是否符合检索方案的预期 |

通过标志：所有已知缺口已列出并说明理由；全文不使用「全面检索」「穷尽」等无法证明的表述。

## 二、召回效果

1. **逐篇核查已知文献**。核对种子及已知关键文献是否符合检索范围，再用题名或稳定标识符检查目标库是否收录。如果手头还有几篇已知相关文献，且拟检索词时没用过它们，可以用来另做抽查。
2. **记录文献是怎么找到的**。逐篇注明是检索式命中、引文追踪等补检找到、手工加入，还是尚未找到。手工加入的文献保留来源，仅将检索式实际命中的文献计入该式的命中检查。
3. **诊断漏检**。对符合边界且确认已收录的漏检，检查主题词、自由词、字段、过滤条件和查看范围。记录原因及调整后复测结果。未收录、超出边界或收录无法核实的条目另列。

确认每篇已知文献的来源有据可查，并复核检索式漏掉的文献。还有漏检未解决时，将此项记为未通过。若报告命中比例，注明分母为符合边界且确认被该库收录的抽查文献，结论限于这组文献。

## 三、元数据完整性

对每条候选检查五个字段：题名、作者、年份、来源（期刊 / 平台）、稳定标识符（DOI / 知网编号）。

- 缺失字段逐条标注原因（平台未提供 / 抓取失败 / 来源本身无）；
- 稳定标识符缺失比例高时，回到来源平台补录，不留着不管；
- 用标识符及题名、作者、年份核对作品。同一作品合并发现记录，保留版本关系。疑似重复待核；同一项目的不同论文分别保留。
- 理论著作或政策原文缺 DOI 时，核对 ISBN 与版本、文号或官方原始链接等可用依据。

通过标志：字段缺失均有标注；版本归并完成且有记录；无静默删除。

## 四、可定位性

随机抽查若干条候选，每条都能还原完整命中路径：**来源渠道 → 检索式、引文追踪起点或手工来源 → 日期 → 原始链接 / 标识符**。如果有一条无法追溯，就补齐检索记录后再交付。

通过标志：抽查全部可还原。

## 停止与交付

建候选池时，完成预定的检索和补检后，按检索方案核对连续两轮补检是否找到了新的高相关文献。只查指定作品或核对出处时，记录核验依据和可访问状态后即可交付。达到停止条件时记录本轮结束原因。若先触及资源上限，或有预定路径未执行、检查未通过，标明阶段性交付并列出待补事项。

两种状态均用[检索方案模板](search-contract.md)交付检索台账、候选清单和覆盖缺口说明。检查候选清单中的发现编号能否在台账查到。

未获全文的条目不在本阶段追索到底——标注真实状态后移交下游，由筛选阶段按边际价值决定是否继续获取。
